# 生成引擎

## Summary

带种子的确定性填字布局引擎：在经典放置规则下把词表编织成报纸风
网格，并从多轮随机尝试中挑出最优。

## Background

手工做一张填字要找互相咬合的单词、核对每个交叉字母、避免意外单词、
再给网格编号——老师只想出一张词汇练习卷，却要耗上几小时试错。现有
生成器要么是 App、要么要账号，产出的也常是违反填字惯例的松散
「单词搜索」式网格。

## Problem

项目需要的生成器要：(a) 构造上正确——交叉永远一致、不出意外相邻
串词；(b) 诚实——放不下的词连同原因报告，绝不悄悄丢弃；(c) 在浏览器
里快到即时；(d) 测试可复现，算法改动无需人工盯网格即可验证。

## Goals

- 每个放置的词都遵守经典填字规则（交叉字母一致、禁止并行重叠、
  禁止意外相邻字母串）。
- 最终网格采用标准 Across/Down 编号。
- 在很宽的词量范围内给出紧凑、报纸风布局。
- 同种子 → 同网格（确定性）；每次生成 → 新种子（有变化）。
- 放不进的词带机器可读的原因码上报。
- 纯逻辑、零 DOM 依赖，可在 Node 运行以供测试。

## Non-Goals

- 密码式（cryptic）填字语义或线索生成（线索是独立关注点，见
  [AI 线索撰写](./ai-clues.md)）。
- 自由式「单词搜索」「填字格」等拼图类型。
- 支持超过 12 字母的单词或非 A–Z 文字。
- 承诺任何词表都放得满——有些词集确实无法互锁，必须如实报告而非
  硬塞。
- 多词短语（解析阶段即拒绝内部空格）。

## Solution Overview

`js/generator.js` 暴露 `CW.Generator.buildLayout(words, options)`：

1. **稀疏网格** —— 以 `"r,c"` 为键的 `Map`，布局生长期间坐标可为负，
   包围盒最后推导。
2. **规则校验** —— 每个候选放置都检查交叉（字母必须一致）、禁止
   并行重叠、禁止拼出意外单词的相邻字母串。
3. **评分** —— 合法放置按 `交叉数×权重 − 包围盒增长 − 长宽拉伸 +
   抖动` 评分，最优者先放。
4. **多轮重试** —— 失败的词在后续轮次重试，后续放置可能解锁此前
   失败。
5. **择优** —— 运行多次带种子的尝试，按 放置数 → 交叉数 → 紧凑度 →
   方正度 选出赢家。
6. **编号** —— 对选中的网格应用标准填字编号。

难度预设调整密度目标与网格上限（简单密集紧凑、困难开阔稀疏）。

## Detailed Behavior

- 词在布局前清洗为大写 A–Z；3–12 字母。
- 随机数来自 mulberry32（种子经 FNV-1a 字符串哈希喂入）——同种子完全
  确定。
- 结果携带 `entries`（行、列、方向、答案、线索）与 `unplaced`
  （答案、线索、`reasonCode` + 参数）：
  - `noShared` —— 与已放置的单词没有公共字母；
  - `conflicts` —— 有交叉可能但所有位置冲突；
  - `tooLongGrid` —— 超出该难度的网格上限；
  - `default` —— 历史/未知来源。
- 同一布局（同种子）的编号与渲染永远一致。

## User Experience

用户只面对两个控件：**生成填字游戏**与**重新生成**。重新生成换新
种子并重新套用用户改过的线索——「再要一个布局」永远只需一次点击。
放不下的词出现在棋盘下方面板里，附人类可读的原因（UI 负责翻译
原因码）。

## Compatibility and Historical Impact

不影响任何历史行为。引擎输出形状（entries + unplaced 的 layout）是
作答、打印、进度键控与分享链接共同消费的契约，自首发以来保持稳定。

## Data and Privacy Impact

无。生成是纯计算：不写存储、不发网络请求、不触碰用户数据。

## Performance Impact

典型课堂规模（12–30 词）在普通硬件上毫秒级到几十毫秒完成；压力套件
在开发机上 24 次随机子集生成共约 77 ms。对页面加载无可测影响（单
经典脚本模块）。

## Current Limitations

- 非英文及带连字符/重音的词不支持（仅 A–Z）。
- 超大词集可能超出网格上限并报告未放置词。
- 布局质量是启发式的：特定审美理想（如 NYT 主题级最大互锁密度）
  不是目标。
