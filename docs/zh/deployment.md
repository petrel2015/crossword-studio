# 部署指南

Crossword Studio 就是一个静态文件夹。没有后端、没有构建步骤、没有
环境配置——部署等于把文件夹拷到任意静态托管。

## 上传什么

仓库根目录即部署产物：

```
index.html
css/
js/
vendor/        （仅赞赏弹窗的二维码渲染需要）
img/donate/    （仅保留 README 静态二维码小节时需要）
docs/          （可选——文档，应用本身不需要）
```

最小可用部署：`index.html`、`css/`、`js/`、`vendor/`。应用运行时
不引用其他任何东西（`docs/` 与 `img/donate/` 是给人看的）。

## GitHub Pages（当前托管方式）

在线版跑在 GitHub Pages：<https://petrel2015.github.io/crossword-studio/>

发布或更新：

1. 把文件推到 GitHub 仓库的 `main` 分支。
2. 仓库内：**Settings → Pages** → Source：从分支部署 → `main` / 根目录。
3. 首次发布需要一两分钟；更新通常一分钟内生效。

无需任何子路径适配：`index.html` 中所有资源都是相对路径引用
（`css/style.css`、`js/*.js`、`vendor/qrcode.min.js`），应用在域名根
路径与 `/仓库名/` 子路径下的行为完全一致。

## 其他静态托管

| 托管 | 做法 |
| --- | --- |
| Netlify / Vercel | 拖拽文件夹上传，或连接仓库；无构建命令，发布目录 = 仓库根 |
| 对象存储（S3 / OSS / COS） | 上传文件，开启静态网站托管，索引文档设为 `index.html` |
| 任意 Web 服务器（nginx、Apache、Caddy） | 把文件夹拷进伺服目录——仅此而已 |
| 内部文件共享 | 文件夹从普通文件共享即可使用；用户甚至能用 `file://` 直接打开 `index.html` |

不需要任何服务端重写规则、MIME 覆盖或 SPA 回退——单页应用加相对
资源，仅此而已。

## 缓存刷新

应用很小且没有带哈希的资源文件名。如果你的托管缓存激进：要么给
`index.html` 设较短 TTL，要么更新样式表链接上的版本号（仓库开发期
就用 `css/style.css?v=20260827` 做这件事）。

## 发布后验证清单

- [ ] 打开站点——报头正常渲染，console 无报错。
- [ ] 载入示例 → **生成填字游戏** → 网格出现。
- [ ] 输入一个字母，点**检查**，刷新页面——进度恢复。
- [ ] **分享** → 在无痕窗口打开复制的链接——同一套题载入。
- [ ] **打印 / PDF** → 预览渲染 → 打印对话框弹出。
- [ ] 页脚 ☕ → 赞赏弹窗打开、二维码渲染（验证 `vendor/qrcode.min.js`
      上传无误）。

## HTTPS 与 AI 线索

AI 线索由浏览器直连你配置的接口。若配置了 `https://` 的 AI 接口，
页面也应通过 HTTPS 提供（HTTP 页面发起的混合内容请求会被拦截）。
GitHub Pages 在线版默认 HTTPS。禁止浏览器 CORS 直连的服务商在任何
托管下都无法使用——那是服务商侧的限制，不是部署问题。
